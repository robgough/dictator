# Marketing site screenshots — how they're made

The eight Mac/Meetings shots on `docs/index.html` are **generated by the apps
themselves**, not grabbed by hand. Re-run one command after a UI change and all
eight — plus the off-site `demo-history` shot — are rebuilt from the current code
with fabricated data:

```bash
./scripts/mac-screenshots.sh                 # every shot
./scripts/mac-screenshots.sh today companion # only these
```

Each capture opens a window on screen and takes focus, so name the shots you
need; an app with none named isn't built.

Everything below documents that pipeline. (The iPhone shots are separate — see
the last section.)

## Screenshot mode — the env-var contract

Both Mac apps carry a developer-only screenshot mode. It is **inert unless
`DICTATOR_SCREENSHOT` is set**, so a normal launch is behaviour-identical and
there's no changelog entry for any of it.

| Variable | Meaning |
|---|---|
| `DICTATOR_SCREENSHOT=<shot>` | Which capture to perform. Dictator: `modes`, `assistant-draft`, `hud-styles`, `journal`, `chat`, `demo-history`. Dictator Meetings: `live-recording`, `notes`, `coach`. |
| `DICTATOR_SCREENSHOT_OUT=<path.png>` | Where to write the 2× PNG. |
| `DICTATOR_SCREENSHOT_DATA=<dir>` | Throwaway data root. **Every** persistence path resolves under it. Unset falls back to a per-process temp directory — never the real locations. |

Run one by hand like this (from a build in the scratch derived-data tree, never
from `~/Applications`):

```bash
env DICTATOR_SCREENSHOT=coach \
    DICTATOR_SCREENSHOT_OUT=/tmp/coach.png \
    DICTATOR_SCREENSHOT_DATA=/tmp/shot-data \
    ".screenshots-work/derived/Build/Products/Debug/Dictator Meetings.app/Contents/MacOS/Dictator Meetings"
```

### What screenshot mode redirects or switches off

- **Persistence.** `AppSupportPaths` (DictatorCore) is the single resolver for
  the per-Mac `Application Support/Dictator` tree — models, `local-settings.json`,
  `meetings-local-settings.json`, the mic log, the sound-cue cache, the LLM
  socket, the meeting audio folders. `SyncedStorage.defaultDirectory` is
  redirected too, which takes settings, vocabulary, history, conversations,
  assistant memory, people and every meeting's notes/transcript with it.
  `AppDefaults.shared` stands in for `UserDefaults.standard`.
- **Keychain.** `KeychainStore` short-circuits — a capture never reads, writes or
  deletes a provider key (an unsigned build touching the signed app's items
  would raise a password prompt).
- **The single-instance guard**, so the capture runs alongside the user's
  installed, running copies without quitting or relaunching them. Neither
  `bootstrap()` runs: no hotkeys, no Sparkle, no LLM socket server or client, no
  model preload, no audio, no menu-bar item, no permission checks (permission
  UI renders the granted state).
- Appearance is forced to light (`.aqua`), a 20–30 s watchdog exits non-zero if a
  capture hangs, and windows are placed fully on-screen at a fixed size.

### How the window is rendered

`ScreenshotWindowCapture` (in `Sources/DictatorMac/Screenshots/`) captures the
app's *own* window — no Screen Recording grant, which is the whole point.

- **What works today**: `CGWindowListCreateImage` scoped to the window id.
  The symbol is marked *unavailable* in the macOS 27 SDK, so it's resolved with
  `dlsym` at runtime; capturing a window your own process owns is still exempt
  from the Screen Recording check. Output is 2× (Retina).
- **Fallback**: `NSView.cacheDisplay(in:to:)` on the window's theme frame, used
  automatically if the symbol goes away or the window server returns an empty
  image.
- Two things are load-bearing and non-obvious. `settle()` drains `NSApp`'s
  **event queue**, not just the run loop — the capture never returns to
  `NSApplication.run()`, so activation and key-window events would otherwise sit
  undelivered and every window would render with inactive chrome (grey traffic
  lights, grey "on" switches). And the runner hops off
  `applicationDidFinishLaunching` with a short `DispatchQueue.main.asyncAfter`
  before touching windows, because AppKit only finishes activating the app once
  that callback has returned.

## Where the fixture data lives

All of it is invented. No real contact, client, meeting or dictation appears.

- **`Sources/Dictator/Demo/DemoFixtures.swift`** — the Dictator fixtures
  themselves, shared with the user-facing **Demo mode** (`Sources/Dictator/Demo/
  DemoMode.swift`) so a marketing shot and a recorded demo can never drift
  apart. One cast throughout: Sam Okafor (the user), Priya Natarajan, Tom
  Reilly, the client Northwind, the product Lumenfield. It carries the five
  modes (Quick/Raw, Clean, Polished, Messages bound to Slack + Signal +
  Messages, Email/Polished bound to Mail with "Always use British spelling"),
  seven dictation-history records, three assistant conversations, five
  assistant-memory lines, seven dictionary rules and a Scratchpad note, plus
  ten days of journal entries and the one chat the `chat` shot shows.

  The journal fixtures use a *relative* path template on purpose: the shipping
  default is `~/Documents/Dictator/…`, and `~` isn't redirected by screenshot
  mode, so a capture on the default would write into the real journal. The
  `chat` shot names Notes as the insert target and treats the model as
  downloaded (no model is ever loaded in a capture); both overrides are
  `ScreenshotMode.isActive` checks.
- **`Sources/Dictator/Screenshots/ScreenshotRunner.swift`** — the Dictator side.
  `seedSettings()` / `seedConversation()` / `seedHistory()` push the fixtures
  above into this capture process's throwaway stores. `ScreenshotScroll` is the
  one-slot registry a Settings pane hands its `ScrollViewProxy` to so a shot can
  scroll to a named anchor.
- **`Sources/DictatorMeetings/Screenshots/MeetingsScreenshotRunner.swift`** — the
  Meetings side. `seed()` writes six meetings as ordinary `meta.json` /
  `transcript.json` files into the throwaway synced folder, so the app loads them
  through `MeetingsStore` rather than a UI back door. The featured one, "Q3
  roadmap sync" (38:12, today), carries markdown notes with Summary / Discussion
  / Decisions / Action items, three named speakers, calendar context with
  attendees, a 26-turn transcript, and a coach record (58% talk share, two key
  points covered and one missed, a two-sentence written read). The others are
  "Northwind renewal call", "Weekly 1-on-1 — Tom", "Design review: onboarding
  flow", "Interview — Priya Natarajan" and "Support triage stand-up", dated so
  the sidebar shows Today / Yesterday / Previous 7 Days.
  `liveFixtureSession()` builds a `MeetingSession` in `.recording` at 23:41 with
  live notes, eight live-transcript lines, non-zero meters and coach signals —
  **no microphone, no system tap, no model**.
- The four fixture-application methods on the model types
  (`MeetingSession.applyScreenshotFixture`, and the equivalents on
  `MeetingLiveTranscriber`, `MeetingNotesAccumulator`, `MeetingCoachEngine`) each
  `guard ScreenshotMode.isActive else { return }` on the first line.

## Post-processing and the page

`scripts/mac-screenshots.sh` down-samples each 2× capture with
`sips -Z 1400` (retrying at 1300 if a file lands over 400 KB) and writes it into
`docs/media/`. 1400 px is comfortably above the 1280 px the page renders a shot
at, and PNG keeps UI text sharper than a JPEG would; if a shot ever blows past
~450 KB even at 1300, convert that one to
`sips -s format jpeg -s formatOptions 88` and rename it in `docs/index.html`.

The script prints each file's real pixel dimensions at the end. If a shot's
aspect changes, update the `width`/`height` attributes on its `<img>` in
`docs/index.html` — they only reserve layout space, but wrong values make the
page jump as the images load.

All eight slots are live (`<figure class="shot">` with a plain `src=`). The old
`data-shot=` placeholder mechanism and its `.shot-pending` "Coming" panel are
still in the stylesheet for any *future* slot: to add one, copy an existing
`figure.shot` block, set `class="shot shot--placeholder"`, rename `src=` to
`data-shot=`, and add back a `<p class="shot-pending">` panel.

## Adding another shot

1. Add a case to the relevant runner's `switch ScreenshotMode.shot` and a
   `capture…()` that opens the state you want.
2. Add the shot id to the matching loop in `scripts/mac-screenshots.sh` and a
   `place` line for it.
3. Add the `figure.shot` block to `docs/index.html`.

Candidates, in rough order of value: the notch island mid-dictation with the
live streaming transcript; the transcript page in conversation view; History
with the per-stage breakdown of one dictation; the People editor with recognised
voices.

## iPhone screenshots (separate pipeline)

`docs/media/ios-screenshots/{dictating,keyboard,scratchpad,history}.png` are
derived from `screenshots/6.7/*.png` with `sips -Z 600` (all 276×600).
Regenerate after a UI change with:

```bash
for f in 03-dictating:dictating 05-keyboard:keyboard 07-scratchpad:scratchpad 04-history:history; do
  sips -Z 600 screenshots/6.7/${f%%:*}.png --out docs/media/ios-screenshots/${f##*:}.png
done
```

The row is deliberately four wide — a fifth wraps to 2+2+1 at desktop widths and
the orphan reads as broken.

Note: the current `07-scratchpad` capture shows a "Not syncing with your Mac"
banner, so the caption on the site is worded around it ("Point it at the same
shared folder as the Mac…"). If you re-shoot with syncing configured, the
caption can be simplified.
